# 官網公告處理 SOP

初心官網每貼一篇公告，站上要跟著動的檔案是固定的那幾份。這份文件把過去幾次
（25 週年 17584、魔力盲盒 28 的 17624、七夕禮包 17664）實際做過的步驟寫下來，
之後照著走就好，不用每次重新推理。

公告網址長這樣，末尾數字就是公告編號，本文一律用編號稱呼它：

```
https://cg.originmood.com/NewsContent/zh_TW/mlbb_news_17664.html
```

中間那段前綴有四種，**四種都是公告**，不要只認 `news`：

| 前綴 | 篇數 | 說明 |
| --- | --- | --- |
| `mlbb_news_` | 814 | 絕大多數 |
| `mlbb_notice_` | 50 | 官網索引頁上和 news 混在一起列 |
| `mlbb_other_` | 2 | 2021 年的，索引頁已經不列，網址還活著 |
| `mlbb_info_` | 5 | 同上，都是「精彩時刻（Q&A）」 |

編號跨家族不重複，所以檔名／鍵值只用編號就夠。

---

## 0. 先講最重要的一條：不要跑 sync 腳本

`scripts/sync_official_news.py` 是當初一次性把八百多篇公告灌進來用的**批次**工具。
它會做兩件對現在的資料有害的事：

- 用 `csv.writer` 整份重寫 `專屬寵物.csv`。既有欄位的引號會被重新決定，
  整份檔案的 diff 會炸開，人工修過的格式全部被輾平（`寵物合成-手動校正.md`
  記錄的就是這類事故）。
- 把每一列的 `公告日` / `公告連結` 依它自己的比對結果重設。比對不到的寵物
  會被**清空**，不是保留。

所以：**單篇公告一律手工改資料檔**。那支腳本留著只當作分類規則的參考
（`category_of()` 與 `is_major()` 兩個函式就是下面第 3 節那張表的來源），
真的要重跑整份索引時再另外開一次評估。

---

## 1. 取原文，不要取摘要

公告頁是靜態 HTML，直接抓下來自己解析。**不要**用會摘要的工具讀公告——
機率、素質、屬性這種數字被摘要過一手就不可信了，而且摘要常常會把
「公告沒寫的東西」補成看起來合理的內容。

```bash
curl -sL "https://cg.originmood.com/NewsContent/zh_TW/mlbb_news_17664.html" -o news.html
```

抓下來後把標籤剝掉印成純文字，逐行讀完再開始寫資料。要留意的是：

- **表格是用巢狀 `<td>` 排的**，寵物素質那張表讀起來會是
  「體力 / 36 / 種族 / 人形系 / 力量 / 10 / 技能格 / 8 / …」這種交錯順序，
  不是一列一隻。抄的時候對照欄位名，不要照順序硬吃。
- **寵物圖在表格裡的 `<img>`**，網址是 `files.originmood.com/pic/…/picture/<hash>.gif`。
  哪張圖對哪隻寵物要看它在哪一列，不要靠檔名猜。
- **活動期間常常不在這篇**。禮包、機率類公告多半只有公告日期，期間要去
  當期的維護公告找。**公告沒寫就是沒有，不要推算、不要沿用去年的日期。**

## 2. 這篇公告要碰哪些檔案

| 公告裡有什麼 | 要動的檔案 |
| --- | --- |
| 一律 | `content/data/官方公告索引.csv` |
| 一律 | `content/公告存檔/<編號>.md`（原文備份）|
| 首次公開寵物、或重大開放 | `content/data/官方大事記.csv` |
| 新寵物 | `content/data/專屬寵物.csv` ＋ `public/img/專屬寵物/<名稱>.gif` |
| 新道具、飾品、召喚書、變身卡 | `content/data/道具庫.csv` |
| 有明確起訖時間的限時活動 | `content/data/限時活動.csv` |
| 娃娃扭蛋／盲盒的娃娃 | `content/data/盲盒娃娃.csv`、`content/data/扭蛋機娃娃.csv` |

混合型禮包（像銀河星願七夕禮包，裡面同時有召喚書、飾品、消耗品、變身卡）
**整包收進 `道具庫.csv`**，不要拆到娃娃表——那兩份只放娃娃。

## 3. 各檔案的寫法

### 官方公告索引.csv

每一篇都要收，包含維護、機率、補償這種例行公告。**最新的排最上面。**

```
日期,類別,重點標記,開放內容說明,公告,解析寵物數,公告連結
2026-08-19,節慶／活動,,,星河無垠 情義無價 七夕限定召喚浪漫登場！,2,[查看](https://…_17664.html)
```

`類別`從既有六個值裡挑，**由上往下第一個命中的就是答案**（順序有意義，
節慶排在寵物前面，所以七夕的寵物公告算節慶）：

| 類別 | 標題出現這些字 |
| --- | --- |
| 賽事 | PVP、爭霸賽、比賽服、冠軍、亞軍 |
| 職業／系統 | 新職業、職業、系統、星圖、技能、視窗、跟隨 |
| 地圖／任務 | 地圖、村、大陸、海底、天空、迷宮、道場、任務、試煉、塔、聖域、宮、禁地 |
| 節慶／活動 | 週年、新春、春節、元宵、情人節、端午、七夕、中秋、萬聖、聖誕、感恩節、回歸 |
| 寵物／秘寶 | 有寵物，或標題有「寵物」 |
| 活動／營運 | 以上都不是 |

`重點標記`只在維護公告開放了新東西時填，搭配`開放內容說明`寫開了什麼。
禮包、機率類公告兩欄都留空。既有的用詞就這六個，多個用 `、` 連：

```
新任務 / 限時任務 / 新地圖 / 新職業 / 地圖預告 / 內容預告
```

`開放內容說明`照「開放<種類>：<名稱>」的句型寫，多項用 `；` 隔開，例如
`開放限時任務：幽靈道場`、`開放主線任務：救贖之子；開放技能任務：心眼`。

`解析寵物數`是這篇公告裡出現的寵物筆數，沒有就寫 `0`。**這一欄是在描述公告，
不是在描述我們收了幾隻**，所以填之前要確定 `專屬寵物.csv` 真的也補進去了，
否則之後看索引會以為這篇處理完了。

### 公告存檔.md

每篇都要留一份原文備份，檔名就是編號，frontmatter four 欄照既有的寫：

```
---
編號: "17664"
標題: "星河無垠 情義無價 七夕限定召喚浪漫登場！"
日期: "2026-08-19"
原始網址: "https://cg.originmood.com/NewsContent/zh_TW/mlbb_news_17664.html"
---
```

`編號`與`日期`一定要加引號，不然 YAML 會自作主張轉成數字與日期物件，build 直接掛掉。

內文是官網原文剝掉樣式後的 HTML，規則是：`<span>` 全部拆掉（都只是字級與顏色）；
只留 `td` 的 `colspan`/`rowspan`、`a` 的 `href`、`img` 的 `src`/`alt`；
斷行一律寫成 `<br />`；整份**不能有空行**，有空行的話 markdown 會把後半段
當內文重新解析，表格會爛掉。圖片抓進 `public/img/公告存檔/`，
檔名沿用官網那串 hash。

### 官方大事記.csv

欄位和索引一樣，只有第六欄改成`首次公開寵物`（多隻用 `、` 連）。
**不是每篇都收**，判準是：

- 有首次公開的寵物 → 收。連機率公告也收，魔力盲盒 16／26／27 都在裡面。
- **維護公告只要在索引裡填了`重點標記`就收**（開了新任務／新職業／新地圖／
  限時任務的那種）。這條比下面的「維護不收」優先——查過既有資料，
  32 篇填了`新任務`的維護公告全部都在大事記裡。
- 沒寵物、也沒`重點標記`，而且標題是維護、停機、延遲、異常、修復、補償、
  概率、機率、登入、調整、重賽這類例行公告 → 不收。
- 沒寵物但有週年、新地圖、新職業、資料片、開放、登場、降臨、活動這類訊號 → 收。
  季賽開賽（「任務爭霸賽第 N 季開啟」）照慣例都收，只有它的異常／延期公告不收。

### 專屬寵物.csv

新公告的寵物**插在檔頭第一列**（緊接 header），不是 append。

```
名稱,種族,體力,力量,防禦,速度,魔法,技格,總檔,屬性,技能,公告日,公告連結,image,任務用途,入手方法,入手類型
織女星,人形系,36,10,10,19,50,8,125,地10,精神衝擊波LV10、補血魔法LV6,2026-08-19,[公告](https://…_17664.html),/img/專屬寵物/織女星.gif,,銀河星願七夕禮包：織女星召喚書（5%）,活動
```

- `技能`**不收「攻擊」「防禦」**，那兩個每隻都有。多個技能用 `、` 連。
- `技格`是公告的「技能格」，`總檔`是「能力總檔」。
- `公告連結`固定寫 `[公告](網址)`。
- `image` 是 `/img/專屬寵物/<名稱>.gif`，縮圖 `public/img/thumb/專屬寵物/` 可有可無，
  沒有的話畫面層會退回原圖（目前 1079 隻裡有 590 隻有縮圖）。
- `入手方法`寫得到手的實際路徑與機率，例如
  `銀河星願七夕禮包：織女星召喚書（5%）`、`魔力盲盒（28）：黃金虎人召喚書（1%）`。
- `入手類型`只有三種：`活動`（限時活動或限定禮包）、`捕捉`（野外抓）、
  留空（常駐商城、盲盒等）。

**下載寵物圖後一定要打開來看過再寫進資料**。公告表格的圖片順序偶爾與文字錯開，
肉眼確認長相和公告描述對得上（「星河舞姬」是舞者、「大地守望者」是持斧壯漢）
才算數。

### 道具庫.csv

`名稱,分類,子分類,等級,說明,入手方式,image`

`分類`用既有值：`召喚書`、`飾品`、`道具`、`材料`、`合成材料`、`活動道具`、
`設計圖`、`武器`、`防具`、`採集`、`料理`、`藥水`。
`子分類`視情況補（`頭飾`、`耳環`、`戒指`、`變身卡`、`卷軸`、`寵物設計箱`…），
新的子分類值可以直接加，不用先問。

`說明`把機率和官方效果文字寫在一起，用 `；` 分段：

```
織女星召喚書,召喚書,,,抽取機率 5%；使用後可隨機召喚一隻『LV1織女星』作為自己的寵物。,公告：[17664](https://…_17664.html)；銀河星願七夕禮包（抽獎）,
```

`入手方式`的格式是 `公告：[編號](網址)；<來源>；<代價>`，例如：

```
公告：[17584](…)；25週年紀念幣兌換（里謝里雅堡 44,86）；紀念幣×1000
公告：[17664](…)；銀河星願七夕禮包（抽獎）
```

**座標帶半形逗號，整格要用雙引號包起來。**其餘情況一律用全形
`，、；（）`，就不必引號。

數值區間用 `~` 不用 `-`（`生命+（100~200）`），對齊 `特殊飾品頭飾.csv` 的寫法；
公告寫 `-` 是它的排版習慣。公告本身漏標數值時照抄並註明，例如
`必殺+5，命中（公告原文未標命中數值）`，不要自己補一個數字上去。

### 限時活動.csv

`活動,期別,開始,結束,頁面,公告日,關聯內容,官方公告,備註`

時間寫 `YYYY-MM-DD HH:MM`（台灣時間，畫面層會補 `+08:00`）。
**公告沒有明確起訖時間就不要建列**——這份資料是全站活動提醒條的來源，
日期錯了會出現「進行中」的假訊息。

公告本身寫錯（例如把結束年份打錯）而手動修正時，`備註`要加**繕誤**註記，
寫明公告原文與修正原因。

## 4. 收工前的驗算

這幾條每次都要跑，過去抓到過真的錯：

```bash
# 1. 素質合計 == 能力總檔
python -c "
import csv
for r in list(csv.DictReader(open('content/data/專屬寵物.csv',encoding='utf-8-sig')))[:N]:
    s=sum(int(r[k]) for k in ['體力','力量','防禦','速度','魔法'])
    assert s==int(r['總檔']), (r['名稱'], s, r['總檔'])
"

# 2. 同一個禮包／盲盒的機率合計要是 100%
# 3. 每份改過的 CSV：BOM 還在、沒有 CRLF、每列欄數一致
python -c "
import csv
for f in ['專屬寵物','道具庫','官方公告索引','官方大事記']:
    p=f'content/data/{f}.csv'; raw=open(p,'rb').read()
    rows=list(csv.reader(open(p,encoding='utf-8-sig')))
    assert raw[:3]==b'\xef\xbb\xbf' and b'\r\n' not in raw, p
    assert len({len(r) for r in rows if r})==1, (p, {len(r) for r in rows if r})
"
```

再加上：

- 新寵物名稱在 `專屬寵物.csv` 和 `魔力原始寵物.csv` 都**不存在**（避免重複建檔）。
- `npm run build` 要過，頁數應該只多出新寵物那幾頁。
- 建完抽查 `dist/寵物資料/<名稱>/index.html`，確認素質、屬性、技能、圖片路徑都在。

> 注意各 CSV 的 BOM 慣例不一致：`content/data/` 大多數檔案有 BOM，但
> 稱號／聲望／練功那一批手寫的沒有。**照原檔的樣子存回去**，不要統一。

## 5. commit 怎麼切

依 CLAUDE.md 的分層原則：

- 資料層一個 commit（CSV ＋ 圖片可以同一個，圖片是資料的一部分）。
- 畫面層另一個 commit。
- 例外：新增資料**同時**新增對應介面時可以合併。

commit 訊息要寫清楚**新增／刪除／更新了什麼**，以及素質、機率這些數字的
來源公告編號與日期，讓之後被回報「跟公告不符」時查得到根據。


## 7. 目前已知的缺口

17564～17664 那 8 篇已經處理完（專屬寵物 +12、道具庫 +53、索引 +8、大事記 +5、
限時活動 +1）。剩下這些：

- **`限時活動.csv` 缺兩檔活動**：17614 的「八月龍族寶盒」（2026-08-08 12:00 ～
  09-09 12:00）站上還沒有對應頁面，沒有頁面就沒地方連，先不建列；17664 的七夕
  禮包則是公告本身沒寫期間，之後找到帶日期的維護公告再補。
- 「王者道場試煉」只建了 25 週年這一檔（2026-08-13～08-27），**更早的幾期
  （如 2026-05-21～06-11）沒有回填**。
- 魔力盲盒（28）17624 只收了黃金虎人這隻寵物，**那篇的道具機率表整張還沒進
  `道具庫.csv`**。
- 烏拉有一組**隨機初始技能**（精神衝擊波LV10、超強酒醉魔法LV10、強力補血魔法LV6），
  `專屬寵物.csv` 沒有備註欄位可以放，目前只記了固定的那組。要記的話得先加欄位。

另外記一條**不是缺口、但每次都會被誤判成缺口**的事：

- 公告裡冠亞軍寵與其他寵物**共用立繪是正常的**。17644 的「25週年慶使魔」與
  「第19期PVP亞軍寵」指到同一個圖片 hash，17614 的「傑特」與「白傑」也是。
  16984／17114 兩篇寫明冠亞軍寵由奪冠隊伍從既定造型清單挑選、且「寵物不可變色」，
  所以官網原圖本來就一樣。先前拿已收錄的「改造布偶夏莉」對照過，圖片位元組相同、
  素質也完全吻合，確認公告表格的圖文是對齊的，不是錯位。
