## 這個 repo 怎麼分層

核心原則是**資料和介面分開**：改內容的人不必碰程式，改版面的人不必碰內容。

```
content/          ← 資料層。編輯者只需要動這裡
  pages/**.md       每頁的文字內容（frontmatter + Markdown）
  data/*.csv        表格資料（寵物、道具、掉落…），可用 Excel / Google Sheets 開
  images.json       每張圖的原始出處，留著備查用
  nav-order.json    導覽排序，抄自原站（原站是人工排的，照字典序會完全不一樣）

public/img/       ← 圖片實體，已從原站與第三方站抓回本地
  thumb/**          表格用的 80x80 縮圖（見下方「表格圖片為什麼有兩份」）
src/              ← 介面層。版面、樣式、元件
  content.config.ts   內容欄位的 schema，缺漏會讓 build 失敗
  layouts/            整體版面（含導覽與頁尾）
  components/         DataTable（資料表）、SourceNote（來源標示）
  styles/global.css   所有顏色與版面都在這支
```

整個網站只需要 Node，沒有其他執行期相依。

### 編輯者要知道的事

想幫忙補資料的話，改 `content/` 就好，不需要懂 Astro 或 HTML。
有問題可以到 [DC 群](https://discord.gg/F5gqG8Grk9) 問。

- **改文字** → 找 `content/pages/` 裡對應的 `.md`，改 `---` 底下的內容
- **改表格** → 找 `content/data/` 裡的 `.csv`，用 Excel 或 Google Sheets 開
  - 欄位可以自己增減，表格會照著長，不用改程式
  - 有 `image` 欄的話，會自動顯示成縮圖
  - 儲存格裡寫 `[文字](/任務攻略/...)` 會變成連結，見下方「表格裡的連結欄」
  - 一格要放好幾條（像一個道具有好幾個採集點）就用 ` / ` 隔開，
    表格會渲染成一行一條。前後的空白是分隔符的一部分，不能省
- **補練功地點／路線**（推薦練功攻略頁）→ 兩份 CSV，地點只有一份定義：
  - `data/練功地點列表.csv` 一列一個練功點。「分區」決定歸在哪一區；
    「適合等級」是玩家適合練的等級（怪物等級另有欄位）；「標記」放
    難度高這類提醒；「進入條件」寫 `類型：內容`（任務／物品／稱號／
    等級／費用／密語／隊伍／時段），多條件用 `；` 隔開
  - `data/練功路線.csv` 一列一條推薦路線（只有名稱與說明）。地點屬於
    哪些路線寫在地點列表的「路線」欄，一格多條用 ` / ` 隔開——路線
    不複製地點資料，改地點一處就全處生效；「標記」則是地點自己的
    提醒（難度高、推算…），兩者性質不同，不共用欄位
  - 還沒整理的值寫 `待補` 或留空，頁面會標示出來，不會壞
- **換圖** → 放進 `public/img/`，在 CSV 或 Markdown 裡寫 `/img/...`
- **搬頁面** → 改完檔案位置，記得去 `astro.config.mjs` 的 `moved` 補一筆轉址，
  舊網址才不會直接死掉（GitHub Pages 沒有伺服器端轉址，靠 Astro 產一張 meta refresh）
- 每頁的 `sourceUrl` 是這頁的出處，全站底部會自動顯示。多數是原站頁面；
  也可以填別的站（料理配方就填蔚藍幻境），底部會改成顯示網域並標「外站資料」。
  自己編的索引頁沒有出處，整個欄位不要寫

### frontmatter 欄位

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `title` | ✓ | 頁面標題 |
| `sourceUrl` | | 這頁的出處，用來標示來源；自己編的頁面留空 |
| `breadcrumb` | | 上層分類，決定導覽位置 |
| `datasets` | | 要顯示哪些 `content/data/*.csv` |
| `order` | | 排序權重，小的排前面 |
| `draft` | | `true` 就不會出現在導覽 |

### 原站顏色怎麼處理

原站用內嵌顏色表達語意（紅＝重點、紫＝掉落道具、褐＝怪物名…）。
內容層不存顏色，只存語意標記：

```html
<span class="hl-key">神血密封瓶</span>
```

實際顏色定義在 `src/styles/global.css` 的 `--hl-*`，要改配色只改那一支。

| class | 原站顏色 | 語意 |
| --- | --- | --- |
| `hl-key` | 紅 | 重點、關鍵條件 |
| `hl-drop` | 紫 | 掉落道具與機率 |
| `hl-npc` | 深黃 | NPC |
| `hl-mob` | 褐 | 怪物 |
| `hl-ref` | 藍 | 交互參照 |

內容層還會用到這幾個結構標記，長相同樣定義在 `global.css`：

| class | 用途 |
| --- | --- |
| `sitebtn` | 原站的按鈕元件（首頁那排「初心官網」等） |
| `carousel` | 一組輪播圖，渲染成可橫向滑動的圖庫 |
| `linkcards` / `linkcard` | 分類連結卡（職業總覽） |

### 表格裡的連結欄

儲存格可以用 Markdown 連結語法 `[文字](/路徑)`，渲染時會轉成 `<a>`。
除了連結以外的內容一律當純文字逃逸——CSV 是資料不是模板，不該能塞 HTML 進來。

只要**某一欄有任何一格出現連結**，表格就會自動多一個「只看有這欄的」勾選框。
這是給那種「只有少數列有值的補充欄」用的，判斷條件寫在 `src/lib/datasets.ts`
的 `noteColumn`，不綁欄位名字——之後別的 CSV 加同樣形態的欄位也會自己長出來。

現在用到的是寵物表的 **`任務用途`** 欄：有些寵物帶在身上就能讓任務少走一段
（直接登頂、跳過關卡王、免掉通行證），這件事原本只寫在各攻略頁的一行小字裡，
翻寵物表的人根本看不到。36 隻寵物標了這欄，每一條都連回對應攻略頁。

### 表格圖片為什麼有兩份

寵物頁有 1069 列，每列一張圖。表格裡只顯示 40x40，但原圖是給滑鼠移過去的
放大預覽用的，最大那張（裁決白龍王）有 280x332、112 幀、2.6MB。
兩邊共用同一個檔的話，等於為了畫一個 40px 的縮圖去載 2.6MB。

所以表格那張改用 `public/img/thumb/` 底下的 80x80 縮圖，原圖只留給放大預覽。
預覽那張是 `display:none` + `loading="lazy"`——瀏覽器不會事先下載（實測確認過），
真的 hover 才抓，所以不需要任何 JavaScript。

實測寵物頁：

| | 之前 | 之後 |
| --- | --- | --- |
| 初次載入 | 1.77 MB | **0.49 MB** |
| 從頭捲到尾 | 55.9 MB | **19.0 MB** |

縮圖是**選擇性**的：`src/lib/thumbs.ts` 找不到縮圖就用原圖。
所以新增圖片時不做縮圖也不會壞，只是那一張會載得比較肥。
（縮圖只在能省 20% 以上時才產生，不然徒增檔案數。）

## 部署

推到 `main` 就會透過 `.github/workflows/deploy.yml` 自動部署。

網站路徑靠兩個環境變數決定，內容本身不綁定部署位置：

| 情境 | `SITE_URL` | `BASE_PATH` |
| --- | --- | --- |
| 組織／使用者頁（repo 叫 `<owner>.github.io`） | `https://<owner>.github.io` | `/` |
| 專案頁（其他 repo 名稱） | `https://<owner>.github.io` | `/<repo>` |
| 自訂網域 | 該網域 | `/` |

前兩種 workflow 會自己判斷，不用設定任何東西——repo 名稱等於 `<owner>.github.io`
就掛在根路徑，否則掛在 `/<repo>` 底下。判斷錯的話全站連結與圖片都會 404。

要覆寫（例如自訂網域）就到 repo 的
Settings → Secrets and variables → Actions → Variables 設 `SITE_URL` / `BASE_PATH`。

## 內容是怎麼來的

`content/` 底下的 177 頁與 312 份 CSV 是一次性從
[原站](https://sites.google.com/view/goodluck2cg/) 轉換過來的，圖片也在當時鏡像到
`public/img/`（1355 張，做過一次驗證式無損壓縮）。

搬遷用的 Python 腳本**沒有留在 repo 裡**——搬完就不會再跑，留著只會讓人誤以為
維護這個網站需要 Python。之後所有修改都直接改 `content/`。

有幾件事情是搬遷時就固定下來的，改內容時知道一下比較不會踩到：

- **有一條連結跟原站不一樣，這是刻意的。**
  原站「奧德希爾德的召喚」的連結指向一個它自己也 404 的路徑，這裡改成正確的
  `/任務攻略/主線任務/傳說之劍系列/奧斯希爾德的召喚`。別「照原站修回去」。
- **「貪慾牛魔」的「慾」是刻意改的。** 家族任務賽原本寫「貪欲牛魔」，但寵物表、
  圖檔名與官方公告都用「慾」（同一行的「貪慾水晶」也是），寫「欲」會讓這隻寵物
  在站內搜不到。別改回去。
- **43 隻寵物的數值跟原站不一樣，以官網公告為準。** 原站抄的技能格與五維有 47 個
  數字跟官方公告對不上，已全部改成公告的值。順帶一提，官網自己也有 5 隻（妖刀、
  和馬、紅唇蝌魚、多刺甲龍、碧水藍菇）五維加總跟能力總檔對不起來，那是公告的筆誤，
  我們照抄不修——要判斷數字對不對，五維加總應該等於總檔。
- **「料理」不是原站的內容**，1～10 級配方整理自[蔚藍幻境](https://cg.skyey.tw/made/03/17.htm)
  （經典版魔力寶貝）。**只到 10 級**——11 級以上永恆初心自己一套，經典版的
  韓式海鮮鍋不適用，收的是本站既有的 S階生產/採集（韓式甜品、日式海鮮飯）。
  1～10 級的部分已經對過遊戲。
- **「武器」「防具」「藥水」同樣來自蔚藍幻境，同樣只到 10 級**，共 363 筆。
  一種製造技能一張表：劍、斧、槍、弓、杖、投擲武器、小刀掛在 `/生產製造/武器` 底下，
  頭盔、帽子、鎧甲、衣服、長袍、靴子、鞋子、盾牌掛在 `/生產製造/防具` 底下，
  那兩頁本身是索引，沒有表。**炸彈、飾品、寶石還沒收**，永恆初心有沒有還沒確認過。
- **「類型」欄只有劍、斧、杖有。** 那三種單手雙手混著出現，其餘每一種都只有一個值
  （弓全是雙手武器、頭盔全是頭部防具），整欄同一個值就不輸出，改寫在頁面說明裡。
  之後補資料時整欄變成同一個值，也照這個做法拿掉。
- **有 27 筆沒有圖，是刻意的。** 蔚藍對部分道具圖做了防盜連，抓回來會是一張
  405x181 的 PNG 橫幅，寫著「此圖片只在蔚藍幻境網站上顯示」——副檔名還是 `.gif`，
  不看檔案內容看不出來，網頁上就變成一張別人的宣傳橫幅冒充道具圖。
  那是站方明確標示不給外站用的圖，**不要想辦法繞過去**，讓那幾列沒有圖就好。
  要補的話請從遊戲裡自己截，或找有授權的來源。
  受影響的是杖 5、帽子 6、槍 4、投擲武器 4、小刀 3、鎧甲 3、斧 2、頭盔 2、弓 1。
- **同一個系列不同階常常共用一張圖**（長劍與麵包劍都是原站的 13926.gif）。
  同網址就是同一份檔案，只存一份，所以有 47 列的 `image` 指到別的成品名——
  不是寫錯。多數落在同一種技能裡，只有一個跨過去：`鞋子.csv` 的妖精鞋用的是
  `/img/防具/蜥蝪靴.gif`。要換成該成品自己的圖就另存一個檔再改 CSV。
- **「採集」也不是原站的內容**，同樣整理自蔚藍幻境，同樣只到 10 級。
  永恆初心沒有的東西已經濾掉：**蓋雷布倫森林**、**光之路**兩張地圖（22 條採集點），
  以及**神聖米**、**茱萸木**、**大黑蝦**三項道具（後兩項原站只寫得出那兩張圖的採集點）。
  還會有別的：外站記的是經典版，跟永恆初心對不上的地方只能靠玩家回報。
  螃蟹的「庫魯克斯島(490,522)」就是這樣補的。發現不對就直接改 CSV。
- **`生產製造.csv` 跟 `S階武器.csv` 是原站同一張表的兩份副本**，只差一格：
  聖弓：綠天星的深海的水晶，一份寫 4 一份寫 1。原站就這樣，沒動它。
- **12 張外連圖救不回來**（巴哈 6、Discord 6），在來源就已經 404。
- **`content/images.json` 記錄每張圖的原始出處**，網站不會用到它，
  但要查某張圖是哪來的（例如權利人來詢問）就靠它。
